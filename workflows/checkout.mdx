# Checkout

**API:** `POST /api/v1/Checkout` · Permission: `checkout.create`

## Transitions

| From | To | Condition |
|------|-----|-----------|
| Available | Assigned | User or Location mode |
| Reserved | Assigned | **User mode only**; assignee must equal `ReservedForUserId` |

Location-mode checkout from Reserved is blocked.

## Steps

<Steps>
  <Step title="Select eligible assets">
    Use `GET /api/v1/Assets/checkout-available`. Whole kits must be included; assemblies must all be `Available`.
  </Step>
  <Step title="Choose assignment mode">
    `CheckoutAssignmentMode.User` requires assignee (company member). `Location` requires site + location; no acknowledgement email.
  </Step>
  <Step title="Validate org targets">
    Optional site/location/department must be physically consistent.
  </Step>
  <Step title="Persist">
    Creates `CheckoutTransaction` (+ attachments), per-asset `AssetAction` (`CheckOut`), sets `PrimaryStatus=Assigned`, assignee/site/location/expected return, custom fields form `Checkout`.
  </Step>
</Steps>

## Validations

- Expected return ≥ checkout date
- Reserved for another user → blocked
- Kit and assembly completeness rules

## Acknowledgements

`POST /api/v1/Checkout/acknowledgement-email` sends HTML email (SMTP) for user checkouts.
